## 一、先建立总概念：引脚 / 外设 / 寄存器

### 引脚是什么

芯片外面伸出来的一根根金属针，**每一根叫一个引脚**。
一根引脚上只有**一根电线** —— 同一时刻**只能传一个信号**。

### 外设是什么

**CPU 只会算数和读写内存。** 它不懂"电压"、不会"发波形"、不懂"计时"。

所以芯片里内置了一堆**助手**，每个只擅长一件事：

| 助手 | 擅长什么 |
|---|---|
| GPIO | 输出/读取高低电平 |
| UART | 把字节变成串行波形 |
| I2C | 用 2 根线接多个传感器 |
| SPI | 用 4 根线高速接设备 |
| ADC | 把电压变成数字 |
| DMA | 搬运工，替 CPU 搬数据 |
| 定时器 | 精确计时 / 产生 PWM |

**关键理解**：**CPU 不直接"拧引脚"，而是往助手们的"记事本"里写指令。**

### "寄存器"是什么

**寄存器 = 助手们的记事本。**

```c
GPIOA->ODR = 0x0020;
```

这行**不是**"给引脚通电"，而是"**往 GPIOA 助手的 ODR 记事本上写一个数**"。
GPIO 助手看到这个数，就去把对应的引脚拉高。

> **所以整条链是**：**CPU 写寄存器 → 外设读到 → 外设去动引脚**。

## 二、什么是"复用"（Multiplexing，简称 AF）

### 问题：引脚不够用

你芯片上有几十根引脚，但想实现的功能有一大堆：
串口发数据、定时器输出波形、ADC 测电压、普通开关……

**怎么办？→ 引脚的功能是可以"切换"的。**

### 比喻：一根电话线，两种用法

| 用法 | 谁在控制这根线 |
|---|---|
| **用法 A**：你拿话筒说话 | **你**在控制 |
| **用法 B**：接上自动答录机，机器自动应答 | **机器**在控制 |

**同一根线，控制权交给谁，它就是什么功能。这就叫"复用"。**

### 代码里怎么体现

**PA5 这根引脚**（你项目里给 RS485 的 DIR 用）：

```c
/* 设定：PA5 由"你"控制（普通输出） */
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;      // PP = 普通推挽输出

/* 然后代码里就能手动开关它 */
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);    // 我手动拉高
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);  // 我手动拉低
```

**PA0 这根引脚**（定时器产生波形用）：

```c
/* 设定：PA0 交给"定时器"控制 */
GPIO_InitStruct.Mode = GPIO_MODE_AF_PP;          // AF = 交给外设
```

**区别就在这个 `Mode`**：

| Mode | 谁控制这根线 | 你要手动写吗 |
|---|---|---|
| `GPIO_MODE_OUTPUT_PP` | **你** | ✅ 每次都要 `WritePin` |
| `GPIO_MODE_AF_PP` | **外设**（UART/定时器/SPI…） | ❌ 外设自己产生信号 |
| `GPIO_MODE_ANALOG` | **ADC** | ❌ 它直接读电压 |
| `GPIO_MODE_INPUT` | **你**（只读） | 读电平 |

> **一句话**：**"复用"就是把一根引脚的控制权，从"你"手里交给某个专门的硬件。**

### 顺便解释一个真实的困惑："舵机谜题"

**你项目里 PA5 配的是"你手动控制"**（普通输出，给 485 的 DIR 用）。

**但代码里又写了**：

```c
HAL_TIM_PWM_Start(s_htim_servo, TIM_CHANNEL_1);   // 想产生舵机波形
```

**问题**：这一句**只是让定时器开始工作，它不会去改 PA5 的"身份"**。
PA5 还是"你手动控制"。

**而定时器的波形实际从哪出来？** 从它**真正对应的那根引脚 PA0** 出来
（CubeMX 里配的是 PA0 为定时器通道）。

**所以**：
- PA5 = 普通开关（485 的 DIR）→ ✅ 正常
- 舵机的波形从 PA0 出去了 → ❌ 接在 PA5 上的舵机收不到

> **一句话**：**"让定时器开始工作"和"这根引脚归定时器管"是两件独立的事。**
> 前者是开机器，后者是接线 —— **线没接对，机器转了也白转。**

## 三、I2C 到底是怎么回事

### 问题：想接两个传感器，引脚不够

```
MPU6050：想要 4 根线（电源、地、数据、时钟）
OLED：   也想要 4 根线
再想接个别的：又要 4 根
```

**引脚很快用完。**

### I2C 的想法：大家共用一对线，靠"叫名字"区分

**比喻：一个大办公室，只有一部电话**

```
        一根电话线
            │
    ┌───────┼───────┐
    │       │       │
  小李     小王    小张        三个人共用这一部电话
  分机01   分机02  分机03
```

**要找人必须报分机号**："喂，请转 **01** 分机。"

**只有 01 分机的人接电话，其余两个人听着但不出声。** 这就是 I2C。

| 办公室 | I2C 术语 |
|---|---|
| 那**一根电话线** | **SDA**（数据线） |
| 说话的**节拍** | **SCL**（时钟线，由主机打拍子）|
| 报分机号 | **设备地址**（MPU6050 = `0x68`，OLED = `0x3C`）|
| 谁打电话 | **主机**（你的单片机）|
| 谁接电话 | **从机**（传感器）|

**所以 I2C 只用 2 根线**（SCL + SDA），**加设备不用加线**。

### 地址为什么有时写 `0x68`、有时写 `0xD0`？

因为**8 位地址的最低位用来表示"读还是写"**：

```
0x68 = 110 1000        （7 位地址）
       ↓ 左移一位，最后一位放读写标志
0xD0 = 1101 0000       （写）
0xD1 = 1101 0001       （读）
```

### ⭐⭐ 核心：为什么 I2C 必须接**上拉电阻**？

**先说 I2C 的一条奇怪规矩**：

**每个设备只能做两件事**：

| 想表达 | 能做到吗 |
|---|---|
| "我要说**低**" | ✅ 能（把线接到地）|
| "我要说**高**" | ❌ **做不到**（它只能"松手"）|

**把每个设备想成一个开关**：

```
        电源（高电平）
          │
      [一个电阻]        ← ★它就是"上拉电阻"★
          │
    ┌─────┼─────┐
    │     │     │
  开关A  开关B  开关C    ← 每个设备就一个开关
    │     │     │
   地     地     地
```

**规则**：
- **谁都不按开关**（都松手）→ 电阻把线**拉到高电平** ✅
- **任何一个按下开关** → 线被接到地 → **变成低电平** ✅

**所以上拉电阻的作用是**：

> **"负责把线恢复成高电平。"**
> 因为设备只会"往下拉"（接地），**没人负责"往上拉"**。

**不接电阻会怎样？**

```
没有电阻 → 大家都松手时，线是"悬空"的
         → 悬空的线电压不确定（可能 1.2V、可能 2V、可能乱跳）
         → 对方根本分不清这是"高"还是"低"
         → 通信完全随机失败 ✗
```

### 为什么 I2C 要设计得这么"别扭"？

**因为它要允许"多个设备接在同一根线上"。**

**如果设备能主动输出高**，就会出现：

```
设备A 想输出高（往线上灌 3.3V）
设备B 想输出低（把线接到地）
        ↓
3.3V 直接通过 A 接到地 → ★短路，烧芯片★
```

**而"只能拉低、高靠电阻"的设计，永远不会有这个冲突**：

| 情况 | 结果 |
|---|---|
| 一个拉、一个松 | 线是**低**（拉低的赢）|
| 都松 | 线是**高**（电阻拉的）|
| **永远不会"对着干"** | ✅ |

> **附带好处**：这天然实现了"**线与**"逻辑 ——
> 只要有一个设备拉低，整条线就是低。I2C 用它实现**应答（ACK）**：
> 从机拉低 SDA 表示"我收到了"。

## 四、为什么"降速"反而更可靠（★ 最反直觉的一节）

### 比喻：两个人在很吵的房间里喊话

**你说一句话，对方要听清，需要什么？**

- 你**说得慢** → 每个字拖得长 → 对方容易听清 ✅
- 你**说得飞快** → 字和字黏在一起 → 对方听错 ❌

**"降速"就是说得慢一点。**

### 但在这个项目里，还有一层更物理的原因

#### 关键事实：电线**不是理想的**

**教科书里的电线**：信号从一头进去，瞬间从另一头出来，形状不变。

**真实的电线（尤其杜邦线）**：

- 有**电阻**
- 有**电容效应**（线越长、和旁边的线越近，电容越大）

**电容效应是什么意思**：

> 电线**像一个小水桶**。你要把电压从 0V 升到 3.3V，
> 得先把这个"水桶"灌满 —— **灌水需要时间**。

**所以真实的高电平长这样**：

```
理想情况：            真实情况：
  ┌─────────            ┌─────────   ← 需要时间才爬上去
  │                     ╱
──┘                  ──╱
（瞬间到位）          （有斜坡）
```

**这条"斜坡"要多久？** 取决于**电阻 × 电容**：

| 因素 | 影响 |
|---|---|
| 线**越长** | 电容越大 → 斜坡越慢 |
| 线**越靠近别的线** | 电容越大 → 斜坡越慢 |
| **上拉电阻越大** | 充电越慢 → 斜坡越慢 |

#### 把两件事合起来看

**通信的原理**：发送方在**每个固定的时间点**（一个"比特时间"）决定线上是高还是低。
接收方在**每个比特时间的中间**去读一下。

**如果"斜坡"太长会怎样**：

```
比特时间 = 10 微秒（对应 100kHz）：
┌──────── 10 微秒 ────────┐
      ╱────────────              ← 斜坡用掉 1 微秒
     ╱                      ← 还剩 9 微秒是稳定的
接收方在中间读 → ✅ 读到稳定的"高"

比特时间 = 2.5 微秒（对应 400kHz）：
┌── 2.5µs ──┐
   ╱─────                     ← 斜坡也要 1 微秒！
  ╱                       ← 只剩 1.5 微秒，而且还没完全爬到顶
接收方在中间读 → ⚠️ 可能读到"不高不低"的中间值 → 判错！
```

**重点**：**斜坡的时长是固定的（由线和电阻决定），但你留给它的时间变短了。**

| 速度 | 比特时间 | 斜坡占的比例 | 结果 |
|---|---|---|---|
| 慢（100kHz）| **宽**（10µs）| 小 | 裕量大 ✅ |
| 快（400kHz）| **窄**（2.5µs）| 大 | 容易判错 ❌ |

### 所以"降速"的本质是：

> **不是"信号变好了"，而是"我给了信号更多时间到达稳定状态"。**

**再回到电话比喻**：

> 那根线"灌满"需要 1 秒。
> - **慢速说话**：每个字持续 10 秒 → 线早就稳定了 → 对方听得清
> - **快速说话**：每个字持续 2.5 秒 → 线还在爬坡你就换字了 → 对方听不清
>
> **线的物理特性没变，变的是你给它的时间。**

### 项目里的具体经过

1. **CubeMX 默认把 I2C 配成 400kHz**（快）
2. 用**杜邦线**接 MPU6050 —— 线比较长、几根挤在一起 → 电容大 → 斜坡慢
3. 结果：**偶尔**判错 → 传感器**偶尔**读失败
4. 现象：`az std` **交替出现 0 和 3000+**
   —— 看起来像"传感器在剧烈振动"，**实际是"偶尔掉线又恢复"**
5. **改成 100kHz**（比特时间从 2.5µs 变成 10µs，宽了 4 倍）→ **稳定了**
6. **为什么能接受这个速度**：只需要 50Hz 采样（每 20ms 读一次），
   **100kHz 完全够用** —— 读一次数据只要几百微秒

> **一句话总结**：
> **"降速"不是让信号变好，是给信号更多时间稳定。**
> **线的物理特性（电容导致上升变慢）没法改，但"每个比特留给它的时间"可以改。**

## 五、把这套思路用在 RS485 上也一样

同样的道理解释了 485 的那个问题（虽然根因不同）：

| 问题 | 表面看像 | 实际是 |
|---|---|---|
| I2C 偶发失败 | "传感器坏了 / 在剧烈振动" | **线材电容 + 速度太快，信号没来得及稳定** |
| 485 首试必失败 | "电气干扰 / 信号质量差" | **从机还在切换收发方向，请求被整帧丢弃** |

**共同点**：**两个都"看起来像硬件故障"，实际都是时序/物理条件问题。**
**共同解法方向**：**先量化、再定位到具体是哪一段的时间不够。**

## 六、一句话速查表

| 概念 | 一句话 |
|---|---|
| **引脚** | 一根线，同一时刻只能传一个信号 |
| **外设** | 芯片里内置的"助手"，各擅长一件事 |
| **寄存器** | 助手们的"记事本"，CPU 写它 = 下指令 |
| **复用（AF）** | 把引脚的控制权交给某个外设 |
| **I2C 上拉电阻** | 设备只会拉低不会拉高，得有电阻负责把线拉回高 |
| **为什么开漏** | 防止两个设备一个输出高一个输出低，直接短路 |
| **降速为什么更可靠** | 不是信号变好，是**给信号更多时间稳定** |
| **上升时间由什么决定** | 电阻 × 电容（线长、线间距离、上拉电阻大小）|
| **DMA** | 搬运是机械劳动，不值得 CPU 亲自做 |
| **为什么用独立调试串口** | 485 挂了调试口还能用，否则你就瞎了 |

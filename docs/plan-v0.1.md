# Modbus Edge Gateway · 边缘智能 Modbus 网关 · 初步规划

> 状态：**草案 v0.1**（2026-09-27），待确认硬件采购与时间节奏后冻结
> 前身：原 smart-env-station 方案推翻，改为升级现有"STM32 + FreeRTOS + Modbus 数据采集器"项目

---

## 1. 一句话定位

**STM32F411 下位机采集传感器 → RS485 Modbus RTU 总线 → ESP32-S3 网关做 LVGL 人机交互 + 轻量模型推理 + WiFi 上云**的双机边缘智能系统。

简历一句话：*设计并实现基于 Modbus RTU 的双机边缘智能网关：下位机 STM32F411/FreeRTOS 完成 8 路传感器采集与 Modbus RTU 从机协议栈（手写实现），上位机 ESP32-S3 完成主站轮询、LVGL 触摸屏交互、TFLite Micro 模型推理与 MQTT 上云。*

## 2. 为什么升级成这个方案

| 维度 | 旧的 Modbus 采集器 | 本方案 |
|------|--------------------|--------|
| 芯片 | 单 F103 | F411（下位机）+ ESP32-S3（网关），双机系统设计 |
| 协议 | Modbus（AI 辅助，没复盘） | Modbus RTU 从机**手写**，讲得清每一帧 |
| 界面 | 无 | LVGL 触摸屏（招聘 JD 高频词） |
| 智能 | 无 | 端侧模型推理（差异化亮点） |
| 联网 | 无 | WiFi + MQTT |
| 与实习/毕设重复度 | 高 | 低（新增 GUI、AI、双机三个面） |

核心卖点：**一个项目覆盖 RTOS + 总线协议 + GUI + 端侧 AI + 云端**，面试可深挖的点足够多。

## 3. 系统架构

```
传感器(全接F411)          下位机 F411                上位机 ESP32-S3            云端
┌──────────┐   I2C/ADC/GPIO  ┌──────────────┐  RS485   ┌──────────────┐  WiFi  ┌──────┐
│ DHT11    │ ──────────────> │ FreeRTOS     │ <======> │ Modbus 主机   │ -----> │ MQTT │
│ 光敏/MQ-2│ ──────────────> │ 采集任务      │  Modbus  │ LVGL 触摸屏   │        │ 服务器│
│ 超声波   │ ──────────────> │ Modbus 从机   │  RTU     │ TFLite 推理   │        └──────┘
│ 人体感应 │ ──────────────> │ 寄存器映射     │  (手写)  │ 报警仲裁      │
│ 心率血氧 │ ──────────────> │ 执行器控制     │          │ 远程命令执行   │
│ MPU6050 │ ──────────────> └──────────────┘          └──────────────┘
└──────────┘
```

**分工原则：F411 只管"采得准"，S3 管"看得懂"。** 原始数据（含 MPU6050 六轴原始值）全部上抛，模型推理放网关侧——这个取舍本身就是面试考点（为什么不在节点上推理：节点算力/内存有限、模型更新要动所有节点、总线带宽足够传原始值）。

## 4. 硬件清单

### 已有（野火小智套件 + 现有板子）
- STM32F411RET6 核心板（Cortex-M4F 100MHz / 512KB Flash / 128KB RAM，比 F103 富余得多）
- DAP-Link（烧 F411）
- RS485 模块 ×2（TTL 转 485，MAX485/MAX3485）
- 传感器：DHT11、光敏、MQ-2、超声波 HC-SR04、人体感应 HC-SR501、心率血氧 MAX30102、MPU6050
- 执行器：蜂鸣器、风扇 + 电机驱动、SG90、RGB LED
- 可选：W25Q64（F411 本地历史缓存）、OLED 0.96（F411 调试显示）

### 需要购买（预算约 150~250 元）
| 物品 | 建议型号 | 预算 | 备注 |
|------|----------|------|------|
| ESP32-S3 开发板 | **ESP32-S3-DevKitC-1 N16R8**（16MB Flash + 8MB PSRAM） | 60~80 | PSRAM 必须有，LVGL 帧缓冲 + 模型都要内存 |
| 一体化屏幕开发板（二选一方案） | 微雪 ESP32-S3-LCD-1.69 / 2.4 寸触摸款，或"ESP32-S3 + 2.8 寸 ILI9341 触摸屏" | 100~150 | **推荐买触摸屏一体板**，免接线、LVGL 例程现成 |
| 杜邦线/面包板 | 已有 | 0 | |

> 买板原则：**屏和 ESP32-S3 尽量买一体的**（如微雪、猕猴桃的 S3 + LCD 套件），卖家提供 LVGL 移植例程，能省 2~3 天踩坑时间。

## 5. 通信设计：Modbus RTU 寄存器映射（草案）

物理层：RS485 两线制，9600 或 115200，8N1。F411 = 从机（地址 0x01），ESP32-S3 = 主机。

| 寄存器地址 | 名称 | 类型 | 说明 |
|-----------|------|------|------|
| 0x0000 | 温度 | uint16 ×10 | DHT11 |
| 0x0001 | 湿度 | uint16 ×10 | DHT11 |
| 0x0002 | 光照 ADC | uint16 | 原始值 |
| 0x0003 | 烟雾 ADC | uint16 | 原始值 |
| 0x0004 | 距离 | uint16 mm | HC-SR04 |
| 0x0005 | 人体感应 | uint16 | 0/1 |
| 0x0006 | 心率 | uint16 bpm | MAX30102 |
| 0x0007 | 血氧 | uint16 % | MAX30102 |
| 0x0008~0x000D | MPU6050 六轴 | int16 ×6 | 加速度+角速度原始值，供模型推理 |
| 0x000E | 采样序号 | uint16 | 主机用于检测数据更新 |
| 0x0010 | 设备状态字 | uint16 | 位图：各传感器在线/故障 |
| 0x0020 | 控制字 | uint16 | 主机→从机：蜂鸣器/风扇/LED 使能位 |
| 0x0021 | 风扇占空比 | uint16 | 0~100 |

- 主机每 500ms 读 0x0000~0x000E（功能码 0x03），下发控制写 0x0020/0x0021（功能码 0x06）
- **从机协议栈自己手写**（帧解析 + CRC16 + 3.5T 帧间隔），这是本项目对旧 Modbus 项目最大的"还债"：上次是 AI 辅助，这次逐行自己写

## 6. 边缘智能方案

| 候选 | 输入 | 模型 | 评价 |
|------|------|------|------|
| **A. MPU6050 动作/手势识别（推荐）** | 六轴时序窗口 | 1D-CNN | 数据好采（拿板子摇几下就是样本）、演示直观（屏幕显示"画圈/拍桌/静止"）、Edge Impulse 全流程现成 |
| B. 烟雾/环境异常检测 | 多传感器特征 | 自编码器/孤立森林 | 有新意但数据难标、演示不直观 |
| C. 心率+活动联合判断 | PPG+IMU | 小 CNN | 需要真人长期数据，周期不可控 |

**选 A**，流程：
1. MPU6050 以 50Hz 采六轴，F411 打包进寄存器，S3 主机轮询拿到
2. S3 侧滑窗（如 2s / 100 样本）→ 推理
3. 训练：Edge Impulse 在线平台（免费档够用）→ 导出 Arduino/C++ 库 → TFLite Micro 部署
4. 也可自己写小 CNN + 简单特征（均值/方差/过零率）作对比实验——面试更有料

## 7. 软件架构

### 下位机 F411（STM32CubeMX + FreeRTOS + HAL）
| 任务 | 优先级 | 周期 | 职责 |
|------|--------|------|------|
| 采集任务 | 3 | 1s | 轮询各传感器，更新寄存器表 |
| Modbus 任务 | 3 | 事件驱动 | USART 中断收帧 → 解析/CRC → 填充/更新寄存器 |
| 执行任务 | 2 | 事件驱动 | 响应控制字：蜂鸣器/风扇/继电器 |
| 看门狗/状态 | 1 | 5s | IWDG 喂狗、传感器在线检测 |

要点：寄存器表用临界区保护；485 收发方向切换用 DE/RE 引脚；IWDG 必须上（工业项目标配）。

### 上位机 ESP32-S3（框架二选一）
| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| **Arduino 框架 + PlatformIO（推荐）** | LVGL / Edge Impulse / Modbus 库全是现成的，落地最快 | 面试含金量略低于 ESP-IDF | 先用它保证做出来 |
| ESP-IDF | 更硬核，FreeRTOS 原生、组件化 | LVGL+模型+WiFi 三者集成的坑多，工期 +1 周 | 时间富余或已有基础再上 |

S3 任务划分（loop 任务 + FreeRTOS task）：Modbus 轮询 task、LVGL GUI task（内核级优先级注意与 WiFi 冲突）、推理 task（每 2s 一次）、MQTT task。

## 9. 风险与预案

| 风险 | 预案 |
|------|------|
| S3 内存不够（LVGL + 模型 + WiFi） | 必须买 PSRAM 版；LVGL 帧缓冲放 PSRAM；模型选小网络（<100KB） |
| 手写 Modbus 卡住 | 保留退路：先用 FreeModbus 库跑通，再逐模块替换成手写 |
| 485 收发切换时序问题 | 用 UART 空闲中断（IDLE）判帧尾；DE 引脚切换时机在 TC（发送完成）中断里做 |
| Edge Impulse 免费档限制 | 退路：手写特征提取 + 自己训小网络（TensorFlow 本地）再转 TFLite |
| 屏幕驱动踩坑 | 买卖家提供 LVGL 例程的一体板，别自己拼屏 |

# 03 · 上手指南（分阶段 + 验收标准）

> 原则：**每个阶段都必须能在"不依赖下一阶段"的前提下验收**。凡是能拆到 PC 上验证的，就绝不留到联调时才发现。
> 阶段 0~2 是单人单板可做的；阶段 3~4 是双机联调；阶段 5~7 是模型与上云。

---

## 阶段 0 · 工具链打通（半天）

**目标**：两块板子都能"改一行、烧进去、看到效果"。

F411：
1. 在野火资料页按板子型号 **`FryPi-STM32F411RET6`** 找资料包（原理图已确认此型号，可直接搜这个丝印）
2. STM32CubeMX 新建工程：选 `STM32F411RETx`，时钟树配 **HSE + PLL → SYSCLK 100MHz**，Debug = **Serial Wire**（别选 JTAG，PA15/PB3/PB4 是 JTAG 脚，选了就少 3 个 GPIO）
3. 打开 `USART1 (Asynchronous 115200)`、FreeRTOS (CMSIS-V1)、`printf` 重定向到 USART1
4. DAP-Link 烧写（Keil MDK / STM32CubeIDE / CLion+OpenOCD 任选），先跑 LED 闪烁（PC13）+ 串口打印

S3：
1. PlatformIO 建 `esp32-s3-devkitc-1` 工程，**确认 PSRAM 打开**（board 参数 `board_build.arduino.memory_type = qio_opi` 之类按板子改）
2. 点亮屏幕，跑通 LVGL demo（`lv_port_disp_init` / `esp_lvgl_port`），确认触摸可用

**验收**：`F411: printf("boot ok")` 能看到；S3 屏幕能跑 LVGL 官方 demo 并触摸响应。

**坑**：CubeMX 里如果开了 JTAG 却没关，PA13-15/PB3/PB4 会被占；`printf` 一定要重定向 `fputc` 并加 `setvbuf(stdout, NULL, _IONBF, 0)`。

## 阶段 1 · 传感器逐个跑通（1.5 天，**分组推进**）

**目标**：**每个传感器单独都有确定的数值**，全部打 `printf` 出来。此阶段完全不碰 Modbus、不碰 RTOS 多任务。

| 分组 | 器件 | 要点 |
|---|---|---|
| ADC（8 路） | 光敏、热敏、电位器、土壤、雨量、MQ-2、MQ-135、火焰 | CubeMX 配 **扫描模式 + DMA 循环**，`HAL_ADC_Start_DMA` 到 `uint16_t adc[8]`；先只做"原始值打印"，**别急着折算物理量** |
| I2C | MPU6050、MAX30102、BMP280、OLED、VL53L0X | 先写 **I2C 扫描程序**（遍历 0x08~0x77）确认地址全部在线，再逐个读 ID 寄存器 |
| 单总线 | DHT11 | 时序敏感，用微秒延时 + 关中断；读失败的常见原因是**上拉缺失**（4.7k~10k） |
| 脉冲 | HC-SR04 | TRIG 10µs 高电平 → 测 ECHO 高电平宽度；**ECHO 必须分压** |
| GPIO 输入 | HC-SR501、人体雷达、循迹 | 先打印原始电平，确认空闲态（避免上电即触发） |
| PWM 输出 | 风扇、电机、SG90、RGB、蜂鸣器 | SG90：TIM 50Hz，`CCR = 500 + angle*2000/180`（µs） |

**验收**：串口每秒打印一行完整数据；对着 MQ-2 吹一口气、遮住光敏、手靠近超声波，数值都要有明显变化。**数值不动 = 没接对，别往下走。**

**坑**：多模块 I2C 上拉并联导致通信失败；ADC 读数跳 ±50 属正常，加中值+均值滤波；MQ 系列需要**预热 20~60 秒**数值才稳定（记得在 README 里写，演示前预热）。

## 阶段 2 · 寄存器表 + FreeRTOS 任务化（1 天）

1. 定义 `reg_bank_t`（或 `uint16_t regs[128]` + 映射宏），A/B/C/E 区先填上假数据
2. 建任务：`task_acq_slow`(500ms)、`task_acq_fast`(20ms，先只自增计数器)、`task_output`、`task_health`
3. 实现**双缓冲 + 窗口序号**（`plan.md` §5.3 / `docs/02` §7），暂时不接 Modbus，先用 `printf` 打印 `win_seq`
4. IWDG 打开（~2s），在 `task_health` 里喂狗；故意在某个任务里死循环验证 IWDG 能复位

**验收**：把 MPU6050 摇一摇，`task_acq_fast` 打印的 6 轴值连续变化；`win_seq` 每 2 秒 +1；拔掉某个传感器，状态字对应位变 0。

**坑**：F411 只有 128KB RAM，**每个任务的栈大小要显式设置并测余量**（`uxTaskGetStackHighWaterMark`）；寄存器表跨任务访问必须加临界区。

## 阶段 3 · 手写 Modbus RTU 从机（1.5 天）★核心

**先脱机验证，再联调**——这是本阶段最重要的一句话。

1. 实现（顺序建议）：
   - `crc16_modbus()` + PC 端单元测试向量对拍（`docs/02` §3.1）
   - USART2 + **IDLE 中断** + DMA 接收，收帧入队
   - `task_modbus` 解析：地址 → 功能码 → 地址范围 → CRC → 组帧
   - FC03 读 A/B 区（先只支持这一个功能码）
   - DE/RE 时序：发送前置位、**TC 中断清零**、之后重启接收
2. 买一个 **USB 转 RS485**（或直接用另一块板子当主机），PC 端开 `Modbus Poll` 或 `pymodbus` 当**主机**读 F411
3. 把 `docs/02` §10 的测试用例逐条过一遍（异常码、静默丢弃、CRC 错注入、压力测试）

**验收**：PC 主机能读到全部 A/B 区寄存器；`01 03 00 4B 02 00 34 BC` 得到异常码 03；连续 10000 帧 `err_crc == 0`。

**坑**（顺序即踩坑概率）：
- CRC 高低字节写反（**先低后高**）
- 接收在发送没结束时就被重新使能 → 收到自己发的数据
- 用阻塞式 `HAL_UART_Transmit` → RTOS 卡顿、丢帧
- 地址不匹配时回了异常帧 → 多从机总线冲突（**必须静默**）
- 9600 能通、115200 不通 → 基本都是 DE 切换时机 + IDLE 判帧没处理好

## 阶段 4 · 双机 485 联调 + LVGL 实时显示（1.5 天）

1. S3 侧建 `modbus_master` task + 请求队列（**唯一总线持有者**，见 `plan.md` §5.4）
2. 先用 `tools/modbus_slave_sim.py`（pymodbus 从机模拟器）把 S3 主机逻辑调通 → 再换真 F411
3. LVGL 界面：实时数值卡片 + 时域曲线（MPU6050 三轴）+ 控制按钮（蜂鸣器/风扇/LED/RGB）+ 诊断页（帧计数/超时/重试/离线状态）
4. 打通控制下发：按钮 → FC06 → F411 执行 → 读回状态字确认

**验收**：屏幕 500ms 刷新实时数据，摇板子曲线跟着动；按钮能控制蜂鸣器与风扇；拔掉 485 后界面 2 秒内显示"节点离线"。

**坑**：LVGL 刷屏与 WiFi 抢 SPI/CPU → GUI 放 core 1、帧缓冲放 PSRAM、开 DMA；主机轮询不要放在 LVGL 的定时器回调里（会拖慢刷新）。

## 阶段 5 · 本地自治与故障降级（0.5 天，性价比极高）

- F411 侧：超过 `0x002A` 未收到主机请求 → 进入**本地自治模式**（`0x0019 = 0`），按 `0x0027~0x0029` 阈值本地报警（蜂鸣器 + RGB），并置 `0x0011.bit3`
- 主机侧：检测到节点离线 → 界面灰显 + MQTT 上报告警
- OLED + EC11/电位器：断网时本地也能看数据、调阈值

**验收**：拔掉 485 数据线，10 秒后 F411 蜂鸣器自动报警、OLED 显示"本地模式"；插回后自动恢复远程受控。

> 这段是"工业网关"与"学生玩具"的分界线，**面试讲这里的收益远大于多接一个传感器**。

---

## 阶段 6 · 数据集 → 模型 → 部署（3~5 天，10/7 之后）

1. **采数据（不依赖 S3）**：在 F411 上加一个"打点模式"，把 100×6 窗口通过 `USART1(CH340)` 直接打印成 CSV 行
2. PC 侧 `tools/capture_window.py` 收串口 → 每个窗口一行，`tools/label_tool.py` 用键盘打标
3. 每类采 50~80 组：**振动任务** = 风扇正常 / 加配重（不平衡）/ 拧松固定螺丝（松动）；**手势任务** = 静止 / 画圈 / 前后摇 / 拍桌
4. `tools/train_mlp.py`：用 **36 维特征**（E 区）训练小 MLP → int8 全整数量化 → `.tflite`（标准化参数随模型一起导出，MCU 侧必须用同一套均值/方差），留出独立测试集，保存混淆矩阵与 PC 端准确率
5. `xxd -i` 生成 C 数组（或直接放进 `model_data.cc`），TFLite Micro 部署，**tensor arena 用 `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`**
6. `tools/verify_tflite.py`：同一份输入在 PC 与 MCU 上跑，结果对拍（避免"部署后精度莫名掉了"）
7. S3 推理 task：从窗口队列取数据 → 推理 → 结果送 LVGL + MQTT；`0x0400` 特征通道做 A/B 对比实验

**验收**：屏幕实时显示分类标签 + 置信度；测试集准确率 ≥90%（3 类任务）；拧松螺丝后 5 秒内出现"松动"告警。

---

## 阶段 7 · 上云 + 收尾（1~2 天）

- MQTT：`telemetry/{id}` 上报（JSON）、`cmd/{id}` 订阅远程控制；断网时 F411 用板载 W25Q128 缓存，恢复后补传
- 文档：README（架构图 + 接线图 + 快速上手 + 演示 GIF）、时序图、寄存器表、帧抓包截图
- 视频：3 分钟演示（正常监测 → 手势/振动识别 → 报警联动 → 断网自治 → 上云）
- Git：分模块提交历史（`feat(modbus): hand-written slave stack`），Gitee 镜像

## 附 · 调试手段速查
| 现象 | 首选工具 |
|---|---|
| 485 收不到/乱码 | 逻辑分析仪抓 A/B 差分前先抓 TTL 侧 TX/RX/DE 三线 |
| 时序类问题（DHT11、超声波、舵机） | 逻辑分析仪 / 示波器 |
| FreeRTOS 卡死、栈溢出 | `uxTaskGetStackHighWaterMark` + `vTaskList` 打印 + HardFault 寄存器 dump |
| 数据撕裂 | 打印窗口序号 + 在临界区加"读期间不允许切换"断言 |
| 随机复位 | 读 `0x0017` 复位原因 + 量 3V3 纹波（大概率是执行器拉垮电源） |

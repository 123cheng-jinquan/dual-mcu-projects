## 1. 物理层与时序参数

| 项 | 值 |
|---|---|
| 总线 | RS485 两线制（A/B/GND），半双工 |
| 帧格式 | 8 数据位 / 无校验 / 1 停止位（8N1），1 字符 = 11 bit |
| 波特率 | **本项目默认 115200**（F411 的 `0x002D`=4、S3 的 `MODBUS_BAUD`、tools 脚本默认值全部对齐）。9600 **仅**用于"链路能不能通"的单点自检 |
| 角色 | F411 = 从机（地址 `0x01`），ESP32-S3 = 主机 |
| 方向控制 | F411 的 `PA1` = DE/RE，发送前置位、**TC（发送完成）中断里清零** |

**帧间隔时间（8N1）**

| 波特率 | 1 字符 | 3.5T（帧静默判尾） | 1.5T（字符间超时） |
|---|---|---|---|
| 9600 | 1.146 ms | **4.01 ms** | 1.72 ms |
| 19200 | 0.573 ms | 2.01 ms | 0.86 ms |
| 38400 | 0.286 ms | 1.00 ms | 0.43 ms |
| 57600 | 0.191 ms | 0.67 ms | 0.29 ms |
| 115200 | 0.0955 ms | **0.334 ms** | 0.14 ms |

> 实现建议：**USART IDLE 空闲中断判帧尾**（硬件帮你判，比软件定时器准） + 一个 5ms 软件定时器兜底（防 IDLE 漏触发）。不要在中断里做解析，`xQueueSendFromISR` 抛给 `task_modbus`。

### 1.1 为什么默认必须是 115200（带宽预算，别用 9600 跑业务）

一个完整六轴窗口 = 5 帧读、约 1315 字节；慢车道 28 个寄存器 = 69 字节/帧，2s 内触发 4 次。

| 波特率 | 窗口读取耗时 | 2s 内总线总占用 | 利用率 | 结论 |
|---|---|---|---|---|
| **115200** | ≈114 ms | ≈138 ms | **≈7%** | ✅ 正常 |
| 9600 | ≈1.37 s | ≈1.66 s | **≈83%** | ❌ 与 500ms 慢车道严重冲突，系统跑不起来 |

所以 **9600 只能用于"从机能不能被读到"的单点自检**，确认通了立刻升到 115200。
若确需降速，必须**四处同改**：CubeMX 里 USART2 的波特率、`0x002D`、S3 的 `MODBUS_BAUD`、以及 tools 脚本的 `--baud`。

## 2. ADU / PDU 格式

```
请求 ADU：  从机地址(1B) | 功能码(1B) | 数据(N B) | CRC16低(1B) | CRC16高(1B)
响应 ADU：  同上（从机原样回地址与功能码）
```
- **CRC16 先发低字节，再发高字节**（这条最容易写反）
- RTU 最大 ADU = **256 字节** → PDU 最大 253 字节
- 地址 `0x00` = 广播：从机**执行但不响应**（仅写操作有意义）
- 地址 `0x01~0xF7`(1~247) 有效；其它地址**静默丢弃，不响应**（不能回异常，否则多从机总线会冲突）

## 3. CRC16（Modbus 多项式 0xA001，反射）

```c
uint16_t crc16_modbus(const uint8_t *buf, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    while (len--) {
        crc ^= *buf++;
        for (uint8_t i = 0; i < 8; i++)
            crc = (crc & 1) ? ((crc >> 1) ^ 0xA001) : (crc >> 1);
    }
    return crc;   /* 发送时先低字节后高字节 */
}
```

### 3.1 测试向量（已用独立实现算过，可直接当单元测试）
| 报文（不含 CRC） | CRC（线上字节序） |
|---|---|
| `01 03 00 00 00 01` | `84 0A` |
| `01 03 00 00 00 0E` | `C4 0E` |
| `01 03 00 00 00 1C` | `44 03` |
| `01 03 01 04 00 64` | `04 1C` |
| `01 06 00 20 00 01` | `49 C0` |
| `01 06 00 21 03 E8` | `D9 7E` |
| `02 03 00 00 00 02` | `C4 38` |
| `01 03 00 4B 02 00` | `34 BC`（数量超限，应回异常 03） |
| `01 83 02` | `C0 F1` |
| `01 83 03` | `01 31` |

> **自检技巧**：把收到的整帧（含 CRC）送进 `crc16_modbus()`，结果应为 `0x0000`（已验证：`01 03 00 00 00 01 84 0A` → 0x0000）。用这个做接收校验比"重算 CRC 再逐字节比较"更省事。

## 4. 支持的功能码

| 功能码 | 名称 | 支持范围 | 边界 |
|---|---|---|---|
| `0x03` | 读保持寄存器 | 全部区块 | 数量 1~**125**；起始+数量不得越界 |
| `0x04` | 读输入寄存器 | （可复用 0x03 实现，用于只读区块） | 同上 |
| `0x06` | 写单个寄存器 | 仅 C 区 | 只读区写入 → 异常 02 |
| `0x10` | 写多个寄存器 | 仅 C 区 | 数量 1~123 |
| 其它 | — | 返回异常码 `0x01`（非法功能） | — |

### 异常响应格式
`地址 | 功能码|0x80 | 异常码 | CRC`
| 异常码 | 含义 | 触发条件 |
|---|---|---|
| `0x01` | 非法功能 | 不支持的功能码 |
| `0x02` | 非法数据地址 | 地址/地址+数量超出映射表 |
| `0x03` | 非法数据值 | 数量越界、写入值超出合法范围、只读区写入 |

### C 区 · 控制与配置（读写，0x0020~0x002F）

> ⚠️ **所有权约定（重要）：C 区只允许主站写，从机只读。**
> 从机的本地行为（阈值报警、自治降级、失效安全）**不得回写 C 区**，只能在"输出仲裁"时把自己的意图叠加到最终输出上。
> 原因：主站下发控制字是"读-改-写"（例如先读 0x0020 再置 bit0），若从机同时写 0x0020，两边会互相覆盖——典型的 RMW 竞争，表现为"蜂鸣器偶尔自己停了"这类难查的问题。
> 从机的本地状态一律通过 **B 区（0x0010~0x001F）**上报，主站读 B 区即可知道从机在干什么。
| 地址 | 名称 | 范围/位定义 |
|---|---|---|
| 0x0020 | 控制字 1 | bit0 蜂鸣器、bit1 风扇使能、bit2 电机使能、bit3 RGB 使能、bit4 舵机使能、bit5 允许本地自治、bit6 清统计（自清）、bit7 保存配置到 Flash、bit8 蜂鸣器长鸣、bit9 **全部输出安全关断**、bit10 强制窗口重采 |
| 0x0021 | 风扇 PWM | 0~1000 |
| 0x0022 | 电机 PWM | int16 −1000~+1000（符号 = 转向） |
| 0x0023 | 舵机角度 | 0~180（0xFFFF = 保持） |
| 0x0024/25/26 | RGB R/G/B | 0~255 |
| 0x0027 | 温度报警上限 | ×10℃ |
| 0x0028 | 烟雾报警上限 | 0~4095 |
| 0x0029 | 心率报警下限 | bpm |
| 0x002A | **通信看门狗超时** | ×100ms，0 = 禁用 |
| 0x002B | 安全状态位图 | 看门狗超时后各输出的固定状态 |
| 0x002C | 从机地址 | 1~247（写入后立即生效并保存） |
| 0x002D | 波特率代码 | 0=9600 1=19200 2=38400 3=57600 4=115200 |
| 0x002E | 采集周期 | ms（慢车道 500 / 快车道 20） |
| 0x002F | 命令寄存器 | 0xA5A5=恢复默认，0x5A5A=软重启 |

> **取值校验（权威清单，与 `regbank.c:validate_c()` 逐条一致）**
> `0x0021 ≤ 1000`、`0x0023 ≤ 180 或 = 0xFFFF`、`0x0024~0x0026 ≤ 255`、`0x002C ∈ [1,247]`、`0x002D ≤ 4`、
> `0x002A ≤ 60000`、`0x002E ∈ [10,60000]`、`0x002F ∈ {0xA5A5, 0x5A5A, 0}`；**其余 C 区寄存器不做范围校验**。
> 越界一律回异常 `0x03`。
> ⚠️ 工具侧的校验若比这张表更严（例如额外限制心率或温度阈值），会出现"在模拟器上失败、在真 F411 上却通过"的不一致——**两侧一律以本表为准**。

### D 区 · 六轴采样窗口（只读，0x0100~0x035B）
| 地址 | 名称 | 说明 |
|---|---|---|
| 0x0100 | 窗口头 | bit15 = 1 表示有效窗口就绪；低 8 位 = 有效样本数（正常 100） |
| 0x0101 | **窗口序号** | 每完成一个窗口 +1（一致性校验用） |
| 0x0102 | 采样率 | ×10 Hz（500 = 50.0Hz） |
| 0x0103 | 窗口时间戳 | 低 16 位，单位 10ms |
| 0x0104~0x035B | 600 个寄存器 | 100 样本 × (ax,ay,az,gx,gy,gz)，**行优先**：样本 0 的 6 轴在前 |

> 主站顺序填充：`for i in 0..99: for axis in 0..5: buf[i][axis] = reg[0x0104 + i*6 + axis]`（注意 int16 大端，Modbus 寄存器本身就是大端）

### E 区 · 特征向量（只读，0x0400~0x0423，F411 侧计算）
| 地址段 | 内容 | 标度 |
|---|---|---|
| 0x0400~0x0405 | 6 轴均值 | int16 |
| 0x0406~0x040B | 6 轴标准差 | int16 |
| 0x040C~0x0411 | 6 轴峰峰值 | int16 |
| 0x0412~0x0417 | 6 轴过零率 | ×100 |
| 0x0418~0x041D | 6 轴主频 | ×10 Hz |
| 0x041E~0x0423 | 6 轴主频带能量占比 | ×1000 |

> ⚠️ **布局是权威定义，只能这样写：`per-feature`（每个特征 6 轴连续）**
> 上表展开后的寄存器顺序为：
> `[mean_ax mean_ay mean_az mean_gx mean_gy mean_gz | std_ax … std_gz | pp_ax … | zcr_ax … | freq_ax … | energy_ax …]`
>
> 另一种常见写法 `per-axis`（`[ax_mean ax_std ax_pp ax_zcr ax_freq ax_energy | ay_…]`）与它是**转置**关系。
> 两者都是 36 维 → 程序不报错、模型照训照跑，但**准确率会掉到随机水平**，而且极难排查（这是本项目最隐蔽的坑）。
> - `tools/train_mlp.py` 必须用 `--feat-layout per-feature`（脚本默认值已对齐此定义）
> - ESP32 侧 `infer_init()` 会用模型包里的 `FEATURE_LAYOUT` 宏做**硬校验**，不符直接拒绝启动推理
> - F411 侧写 E 区时必须按上表顺序逐段写，不要按轴循环

## 7. 数据一致性机制（**v0.1 缺失，必须实现**）

**问题**：S3 分 5 次读窗口，若中途 F411 切了缓冲，前 3 块来自旧窗口、后 2 块来自新窗口 → 训练数据被污染，且极难排查。

**方案（锁定法，推荐）**
1. 采集任务 50Hz 写 `buf[w]`；满 100 样本后在临界区切换 `active = w`、`win_seq++`、`ready = 1`。
2. 从机收到第一个落在 D 区的读请求时置 `win_lock = 1`，并记录 `lock_tick`。
3. `win_lock == 1` 期间**禁止切换缓冲**（采集继续写另一块，满了就覆盖旧数据并置 `buffer_overrun` 位）。
4. 从机收到 `0x0101` 读请求、或 `win_lock` 持续超过 **500ms**，释放锁。500ms 兜底很重要——否则主机读一半崩了，窗口就永远不更新了。
5. 主机侧仍做校验：读前记 `seq0`，读后记 `seq1`，`seq0 != seq1` → 丢弃重读（当 `0x0101` 未被读到时的兜底）。

**主机侧填充顺序**：先读 0x0100~0x0103 头 → 再 5 块数据 → 再读 0x0101 校验。

## 8. 从机状态机（`task_modbus` 实现骨架）

```
IDLE ──(IDLE中断/DMA完成)──> 收到完整帧
  │
  ├─ 长度 < 4 或 > 256            → 丢弃，err_frame++
  ├─ CRC 校验失败                 → 静默丢弃（不回异常），err_crc++
  ├─ 地址 != 本机地址 且 != 0x00  → 静默丢弃（不回异常！）
  ├─ 功能码不支持                 → 回异常 0x01，err_frame++
  ├─ 数量/地址越界                → 回异常 0x02 / 0x03，err_frame++
  ├─ 写只读区                     → 回异常 0x02
  ├─ 只读请求                     → 从影子寄存器取值组帧
  ├─ 写请求                       → 写 控制区 → 置事件通知 task_output
  ├─ 广播(0x00)                   → 执行，不响应
  └─ 正常响应
        ↓
  DE = 1 ──> HAL_UART_Transmit_DMA() ──> TC中断 ──> DE = 0 ──> IDLE
```

**健壮性硬要求（面试必问）**
- 发送期间必须**丢弃/忽略收到的字节**（半双工回环会收到自己发的数据）
- `HAL_UART_Receive_IT` 重启时机：**必须在 DE 拉低之后**，否则会把自己的发送当接收
- 不使用 `HAL_UART_Transmit` 阻塞版（会卡住 RTOS 其它任务）
- 寄存器表读写用 `taskENTER_CRITICAL()` 或双缓冲，禁止在中断里改多字节量
- 所有计数器/状态字在响应中保持一致，不出现"读一半变了"

## 9. 主机侧（S3）调度与重试

| 通道 | 周期 | 内容 | 超时 | 重试 |
|---|---|---|---|---|
| 慢车道 | 500ms | `01 03 00 00 00 1C` | 50ms | 2 次 |
| 快车道 | 2s | 头 + 5 块 + 序号校验 | 60ms/帧 | 2 次 |
| 写车道 | 事件驱动 | FC06 / FC10 | 50ms | 1 次（写重试要幂等：只重试整块写，避免半写） |

- **唯一总线持有者**：`modbus_master` task 消费请求队列，其它任务禁止直接操作 485。
- 统计：`tx_count / timeout_count / crc_err(由异常/静默判) / retry_count` → 上报 MQTT + 显示在 LVGL 诊断页。
- 连续 3 次超时 → 节点离线报警，界面置灰；恢复后自动重连。

- [ ] 正常读全 A/B 区，字段与串口打印一致
- [ ] 边界：读 125 个（成功）、读 126 个（异常 03）
- [ ] 越界：起始 0x0360（异常 02）
- [ ] 写只读区（异常 02）、非法功能码 0x05（异常 01）
- [ ] 非法值：波特率代码 9、地址 0/248（异常 03）
- [ ] CRC 错注入：手工构造错 CRC，从机**静默**（无响应且不崩）
- [ ] 帧间隔：人为在帧中间插入 >3.5T 间隔 → 应被识别为两帧并丢弃
- [ ] 粘帧：两帧无间隔连发 → 至少不能死机（能解析出第一帧更好）
- [ ] 错误地址静默、广播执行不响应
- [ ] 窗口读取期间拔插/重发 → 序号校验逻辑正确（不产生跨窗口拼接）
- [ ] 连续 10000 帧压力测试，`err_crc == 0`、`timeout == 0`
- [ ] 连续 4 小时跑，`0x0016` 运行时间正常增长且无重启（`0x0017` 不变）

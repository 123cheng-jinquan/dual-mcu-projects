# ESP32-S3 声纹门禁网关

> **项目2** 的推理侧固件。配合 `firmware-stm32-ret6/`（采集侧）构成双片架构。
>
> 与项目1（`firmware-esp32/`）**共用同一块 ESP32-S3 板**，通过重新烧写切换：
> ```
> 项目1（Modbus 网关）：cd firmware-esp32            ; pio run -t upload

> ```

## 1. 系统架构

```
   MAX9814 麦克风
        │ 模拟音频
        ▼
┌──────────────────────────┐          ┌──────────────────────────┐
│  STM32F103RET6           │          │  ESP32-S3（本工程）       │
│  【采集节点】             │          │  【推理网关】             │
│                          │          │                          │
│ ① TIM2 触发 ADC1 + DMA   │          │ ④ 收帧 + CRC 校验         │
│    8kHz 硬件采样          │          │ ⑤ 8bit → 12bit 还原       │
│ ② 帧能量 RMS 做 VAD      │  二进制   │ ⑥ MFCC 特征提取           │
│ ③ 采 1 秒（8000 点）      │ ─帧+CRC─→ │ ⑦ 与注册模板算余弦相似度   │
│    8bit 量化打包          │          │ ⑧ 判 PASS / FAIL          │
│                          │ ←────────│                          │
│ 舵机开锁 / OLED 显示      │ PASS/FAIL │                          │
└──────────────────────────┘          └──────────────────────────┘
```

**为什么这样分工**：
- F103 是 Cortex-M3 @72MHz **无 FPU**，算一次 1 秒音频的 MFCC 要几秒
- ESP32-S3 240MHz 双核，几十毫秒就能算完
- ⇒ 「节点负责实时采集、网关负责重计算」是唯一合理的划分
- ⇒ 和**项目1 完全一致的架构思路**（节点采集 / 网关推理），两个项目形成统一体系

## 2. 硬件接线

```
ESP32-S3                     STM32F103RET6 核心板
─────────────────────────────────────────────────
GPIO4   (UART2 TX)  ──────►  PB11  (USART3_RX)
GPIO5   (UART2 RX)  ◄──────  PB10  (USART3_TX)
GND                 ───────  GND              ★ 必须共地
```

**引脚选择理由**：N16R8 模组上 GPIO4/5 空闲且在排针上易接，避开了
`8/9`(OLED I2C)、`10~15/21`(TFT SPI)、`16~18`(RS485)、`19/20`(原生 USB)、
`26~37`(Flash + Octal PSRAM)。

> ⚠️ **两块板各自用自己的 USB 供电**，不要互相供电。

## 3. 通信协议

与 F103 侧定义**必须完全一致**（见 `firmware-stm32-ret6/Core/Inc/uart_proto.h`）。

```
偏移  长度  字段      说明
 0     1    SYNC      固定 0xAA
 1     1    CMD       命令字
 2     1    SEQ       帧序号（0~255 循环）
 3     2    LEN       PAYLOAD 长度（小端）
 5     N    PAYLOAD   数据
5+N    2    CRC16     CRC16-Modbus，覆盖 CMD~PAYLOAD（**不含 SYNC**）
```

| CMD | 方向 | 说明 |
|---|---|---|
| `0x02` | F103→ESP32 | 音频元信息（采样率/点数/块数/位深）|
| `0x01` | F103→ESP32 | 音频数据块（256 字节/块）|
| `0x10` | ESP32→F103 | 判定结果（PASS/FAIL + 置信度 + 相似度 + 耗时）|
| `0x11` | ESP32→F103 | 状态/调试文本 |
| `0x20` | 双向 | 心跳 |

### 数据量

| 项 | 值 |
|---|---|
| 采样率 | 8000 Hz（**不抽取**，保留完整语音频段）|
| 样本数 | 8000（1 秒）|
| 量化 | 12bit → 8bit（取高 8 位，解码左移 4 位还原）|
| 总字节 | 8000 + 32 帧 × 7 开销 = **8224 字节** |
| 传输时间 | **约 0.71 秒** @115200 |

**为什么不做抽取（降采样）**：
最初设计是"2 倍抽取到 4kHz + 8bit"，能压到 4000 字节（0.35 秒）。
但 4kHz 采样 ⇒ 奈奎斯特上限只有 2kHz，而
**区分不同说话人的关键信息（第二、第三共振峰）大量分布在 2~4kHz**。
丢掉这段等于丢掉了音色里最有辨识度的部分 ⇒ **宁多花 0.35 秒也要保留 8kHz**。

**帧同步的两级校验**（`uart_link.cpp` 里的关键设计）：
1. **长度合法性**：找到 `0xAA` 后先读 LEN，若 `LEN > 1024` 说明这个 `0xAA`
   是数据里偶然出现的，直接跳过继续找 → 大幅降低"假帧头"概率
2. **CRC16**：最终确认

另有 **300ms 半帧超时复位**：对端只发一半就跑掉时能自动恢复，不会永久卡住。

## 4. 串口命令（CH343 口，115200）

| 命令 | 作用 |
|---|---|
| `i` | 打印链路统计（帧数 / CRC 错误 / 重同步 / 丢弃字节 / 会话数）|
| `p` | 给 F103 发一条状态消息（验证回传链路）|
| `r` | **模拟发 PASS** 给 F103 |
| `f` | **模拟发 FAIL** 给 F103 |

> `r` / `f` 用于**在识别算法还没做完时先验证回传链路** —— 分层验证，出问题好定位。

## 6. 验证步骤（分层）

### 第 1 层：链路验证（当前阶段）

1. 接好线与 GND
2. 烧写 ESP32，打开 CH343 口的串口监视
3. 在 F103 上**敲 `u`，然后对着麦克风说一句话**
4. ESP32 应打印：

```
[META] rate=8000 pts=8000 chunks=32 rawbits=16 txbits=8
[META] buffer = 8000 bytes (ok)
[RX] chunk 8/32  (2048/8000 bytes)
...
========== SESSION #1 COMPLETE ==========
[SUM] bytes=8000/8000  chunks=32/32  took=752ms
[LINK] frames=33 crcErr=0 resync=0 dropped=0
[AUDIO] 8bit: mean=94 min=24 max=173 p2p=149
[AUDIO] ->12bit: mean=1504 min=384 max=2768 p2p=2384
```

**关键判据**：

| 检查 | 期望 | 含义 |
|---|---|---|
| `chunks=32/32` | ✅ | 一块没丢 |
| `crcErr=0` | ✅ | 数据完整 |
| `->12bit mean` ≈ F103 的 `baseline` | ✅ | 数据真的传过来了 |
| **`->12bit p2p` == F103 的 `p2p`** | ✅ | **传输零丢失** |

## 7. 开发笔记（踩过的坑）

| 坑 | 说明 |
|---|---|
| **`ARDUINO_USB_CDC_ON_BOOT=0`** | Serial 走 UART0(CH343 口) 才能看到 panic 回溯；置 1 只有插原生 USB 口才有日志 |
| **`memory_type=qio_opi`** | N16R8 是 **Octal PSRAM**，用 qio_qspi 会起不来 |
| **CRC 不覆盖 SYNC** | 若覆盖，SYNC 被干扰破坏时整帧会被丢；不覆盖则可以滑动重找帧头 |
| **不要用 `readBytes()` 阻塞收整帧** | 对端发一半断开会把任务卡死；用非阻塞状态机 + 超时复位 |
| **接收缓冲用 `ps_malloc`** | 放 PSRAM，不占内部 RAM（后面 MFCC 还要用内部 RAM 做快速运算）|

# src/ —— 声纹引擎源码（项目二）

> 4 个源文件，按"数据流方向"分三层：**收帧 → 算特征 → 比对 → 分发命令**。

---

## 目录结构

| 目录 | 职责 | 文件 | 依赖 |
|---|---|---|---|
| **`link/`** | UART 链路层：非阻塞收帧状态机 + CRC 校验 | `uart_link.cpp` / `.h` | 无 |
| **`dsp/`** | 信号处理：MFCC 特征提取 + 声纹模板比对 | `mfcc.cpp` / `.h`<br>`speaker.cpp` / `.h` | 无 |
| **`app/`** | 串口命令分发、会话处理（注册/验证）| `main.cpp` | 上面两层 |

**依赖方向是单向的**：`app` → `dsp` / `link`，而 `dsp` 和 `link` 互不知道对方存在。
所以 `mfcc.cpp` 可以单独拿到 PC 上编译测试（这也是为什么 MFCC 自检能跑）。

---

## 为什么这么分

### `link/` 独立出来

收帧状态机是**字节驱动的**（串口中断每来一个字节就喂一次），
和"这些字节代表什么"完全无关。放在 `main.cpp` 里会混在一起，
放在独立的 `link/` 里，它只负责一件事：**把字节流变成一个完整的帧**。

它内部做了三级防线：
1. 滑动找帧头 `0xAA`
2. 长度合理性（>1024 直接丢弃 —— 因为音频数据里平均每 8KB 会出现 31 次假帧头）
3. CRC16 校验

详见 [`../../../docs/protocol.md`](../../../docs/protocol.md)（等等，实际在 `voice-lock/docs/protocol.md`）。

### `dsp/` 是最核心的一层

| 文件 | 内容 | 关键点 |
|---|---|---|
| `mfcc.cpp` | 预加重 → 分帧加窗 → **自写 256 点基 2 迭代 FFT** → 26 个 Mel 滤波器 → log → DCT-II | 84 维超矢量（14 静态 + Δ + ΔΔ，各取均值/标准差）|
| `speaker.cpp` | 模板管理 + 全局 z-score → 加权欧氏 → **高斯核 + σ 自动标定** | σ² 由注册样本两两距离中位数反解 |

**为什么这两个不能合**：MFCC 是"把波形变成特征"，speaker 是"把特征变成判定"。
前者是**信号处理**（可以脱离声纹任务单独用，比如做语音识别），
后者是**模式匹配**（换一套特征也能用）。职责完全不同。

### `app/main.cpp` 只做三件事

1. 串口命令分发（`E`/`V`/`X`/`S`/`C`/`T`/`M`/`H`，大小写都认）
2. 会话处理：收到一个完整音频会话（1 帧 META + 32 帧 DATA）后，调用 `mfccCompute()` → `spkEnroll()`/`spkVerify()`
3. 判定结果回传 F103（`uartLinkSendResult()`）

**它不含任何算法** —— 算法都在 `dsp/` 里。

## 验证过没问题

重组后重新编译通过。改的只有 `platformio.ini` 里补了 3 行 include 路径：

```ini
-Isrc/app
-Isrc/dsp
-Isrc/link
```

**所有 `#include` 一行都没动**（纯搬家）。

## 串口命令（115200）

| 命令 | 作用 |
|---|---|
| `E` | 注册模式 |
| `V` | 验证模式 |
| `X` | 模板交叉验证矩阵（看同一人多段的一致性）|
| `S` | 打印状态（模板数 / 阈值 / σ²）|
| `C` | 清空所有模板 |
| `T0.52` | 设阈值 |
| `M` | MFCC 自检（自比必须 = 1.0000）|
| `H` | 帮助 |

**全部大小写都认**（早期只认小写，敲大写会报 unknown，是个真实的 bug）。

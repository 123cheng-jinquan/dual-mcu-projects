# 算法详解：MFCC 特征提取与声纹模板比对

> **一句话**：把 1 秒 8 kHz 的语音波形，变成**能代表"这个人"的 84 个数字**，再用距离度量判断"像不像"。

---

## 一、整体流程图

```
8000 个样本（8 kHz，1 秒）
        │
        ▼  ① 反量化 + 去直流
   8000 个 int（12 位量纲）
        │
        ▼  ② 预加重（高通滤波，0.97）
   y[n] = x[n] - 0.97·x[n-1]
        │
        ▼  ③ 分帧：25 ms 帧长 / 10 ms 帧移
   98 帧 × 200 点
        │
        ▼  ④ 汉明窗（抑制频谱泄漏）
   98 帧 × 200 点（加窗后）
        │
        ▼  ⑤ 补零到 256 点 + 基 2 迭代 FFT
   98 帧 × 129 个频点（0~4000 Hz，线性）
        │
        ▼  ⑥ 取功率谱 + 26 个 Mel 三角滤波器
   98 帧 × 26 个 Mel 能量
        │
        ▼  ⑦ 取自然对数（模拟人耳的对数感知）
   98 帧 × 26
        │
        ▼  ⑧ DCT-II（离散余弦变换）
   98 帧 × 14 维倒谱系数（c0 + c1~c13）
        │
        ▼  ⑨ 叠加一阶 / 二阶差分
   98 帧 × 42 维（14 静态 + 14 Δ + 14 ΔΔ）
        │
        ▼  ⑩ 对每一维取「均值 + 标准差」（把时间轴压掉）
   ★ 84 维声纹超矢量 ★
        │
        ▼  ⑪ 与注册模板比对（z-score + 加权欧氏 + 高斯核）
   相似度 0~1
```

## 二、每一步为什么这么做

### ① 反量化 + 去直流

```c
int32_t s = ((int32_t)q - 128) * 16;    // q 是收到的 8 位量化值
```

**为什么先减 128**：8 位量化的中点是 128，不减的话会留下一个 **+128·16 = +2048 的直流偏置**。
这个偏置会直接跑到 DCT 的 **c0（第 0 维）** 上，把其他维度淹没。

> 这是实际踩到的坑：一开始忘了减中点，导致 c0 数值巨大、c1~c13 全是噪声。

### ② 预加重（Pre-emphasis）

```
y[n] = x[n] − 0.97 · x[n−1]
```

**作用**：**提升高频**。

**为什么需要**：语音的频谱能量主要集中在中低频（基频 + 前几个谐波），
高频部分（尤其 2~4 kHz 的**共振峰过渡**）能量低但**携带很强的说话人信息**（声道形状）。
预加重把频谱"压平"一点，让高频细节在 MFCC 里能体现出来。

**0.97 的来源**：这是语音处理界的经验值（`1 - e^{-2π·f_c/fs}`，对应约 100 Hz 处的高通转折）。
大多数语音识别系统都用 0.95~0.97。

### ③ 分帧：25 ms / 10 ms

| 参数 | 值 | 为什么 |
|---|---|---|
| **帧长 25 ms** | 200 点 @ 8 kHz | 语音在 **10~30 ms** 内是"短时平稳"的 —— 太短看不到频谱，太长特征会糊 |
| **帧移 10 ms** | 80 点 | **重叠 60%**，避免帧边界处的信息丢失 |

**1 秒音频 → 帧数**：`(8000 − 200) / 80 + 1 ≈ 98 帧`（实测就是 98）

### ④ 汉明窗（Hamming Window）

```
w[n] = 0.54 − 0.46 · cos(2πn / (N−1))
```

**为什么加窗**：直接对 200 点做 FFT，相当于默认这是"一个周期信号"，
但帧边界处**首尾不连续** → 会产生**频谱泄漏**（能量从真实频率"漏"到旁边频点）。
加窗让两端平滑过渡到 0，泄漏大幅减少。

**为什么用汉明而不是矩形/汉宁**：
- 矩形窗：泄漏最严重
- 汉宁窗：旁瓣衰减快但主瓣宽
- **汉明窗**：主瓣窄、旁瓣低（−43 dB），是 MFCC 的**标准选择**

### ⑤ 256 点基 2 迭代 FFT（自写）

**为什么补零到 256**：
- 200 点不是 2 的幂，**基 2 FFT 要求长度是 2 的幂**
- 补零到 256 而不是截断到 128，是为了**保留全部 200 点信息**（补零不改变频谱，只是插值）
- 256 点 @ 8 kHz → **频率分辨率 31.25 Hz**

**为什么自己写 FFT 而不用库**：
1. ESP32 Arduino 环境没有现成的 FFT 库（`arduinoFFT` 是第三方，且是浮点定点混用）
2. **自写能完全控制精度和内存布局** —— 复数用两个 `float[256]` 数组（实部/虚部），
   避免结构体开销
3. 面试时"我手写过基 2 迭代 FFT"比"我调用了一个库"有说服力得多

**实现要点**：
```c
// 第一步：位反转重排（把输入按 bit-reversed 顺序摆放）
for (i = 0; i < N; i++) {
    j = bit_reverse(i, log2N);
    if (i < j) swap(a[i], a[j]);
}

// 第二步：迭代蝶形（log2N 级，每级 N/2 个蝶形）
for (stage = 1; stage <= log2N; stage++) {
    m = 1 << stage;                    // 本级蝶形跨度
    wm_re = cos(-2π/m), wm_im = sin(-2π/m);
    for (k = 0; k < N; k += m) {
        w_re = 1, w_im = 0;
        for (j = 0; j < m/2; j++) {
            u = a[k+j],  v = a[k+j+m/2] * w;
            a[k+j]       = u + v;
            a[k+j+m/2]   = u - v;
            w *= wm;                   // 旋转因子递推
        }
    }
}
```

**自检方法**（很重要）：**自己跟自己比，MFCC 余弦相似度必须 = 1.0000**。
实测：`self cosine = 1.0000`，不同段的互比 = `0.7319` —— 说明 FFT 和滤波器组**实现正确**。

### ⑥ Mel 三角滤波器组（26 个）

**Mel 刻度**：人耳对频率的感知**不是线性的** —— 对低频敏感、高频迟钝。

```
mel(f) = 2595 · log10(1 + f / 700)
```

**做法**：
1. 把 0~4000 Hz 按 Mel 刻度分成 **28 个等距点**（26 个滤波器需要 28 个边界）
2. 每个滤波器是一个**三角形**：在中心频率处为 1，在相邻中心处为 0
3. 每个滤波器的输出 = **该频段内功率谱的加权和**

**为什么是 26 个**：
- 太少（<20）：频率分辨率不够，丢信息
- 太多（>40）：每个滤波器只覆盖几个频点，统计不稳定
- **26 是 8 kHz 采样率下的常见值**（对应 Kaldi/HTK 的默认配置）

**关键**：用**功率谱**（幅度平方）而不是幅度谱 —— 能量的叠加才有物理意义。

### ⑦ 取对数

```
log_energy = ln(sum_of_power)
```

**为什么**：
1. **人耳对声音的感知是对数的**（分贝就是对数刻度）
2. **把"声道传输特性"和"声源激励"变成可分离的加法关系** ——
   这是倒谱分析的核心：`log(激励 × 声道) = log(激励) + log(声道)`
3. 压缩动态范围，避免大能量段主导

### ⑧ DCT-II（把 26 维压到 14 维）

```
c[k] = Σ_{m=0}^{25} log_E[m] · cos(π·k·(m+0.5) / 26)
```

**为什么用 DCT 而不是 DFT**：
DCT 是**实数变换**，输出也是实数（省一半计算），而且**能量更集中**（大部分能量集中在前几维）。

**为什么只保留前 14 维**：
- **c0** 代表整体能量（对应"说得多响"）
- **c1~c13** 代表**频谱包络的形状**（对应"声道形状" = **说话人特征**）
- 后面的高阶系数主要反映**基频的精细结构**（说话内容的音素变化），
  对识别"是谁"帮助不大，反而引入噪声

> **这正是"声纹"和"语音内容"的分界**：低阶倒谱 = 声道 = 人；高阶 = 音素 = 内容。

### ⑨ 一阶 / 二阶差分（Δ / ΔΔ）

**静态 MFCC 只描述"某一帧的频谱形状"，丢失了"频谱怎么变化"的信息。**

**Δ 计算（回归法，K=2）**：
```
Δ[t] = [1·(c[t+1] − c[t−1]) + 2·(c[t+2] − c[t−2])] / 10
```
端点用**复制边界**处理（`c[-1] = c[0]`，`c[-2] = c[0]`）。

**ΔΔ**：对 Δ 再做一次同样的运算。

**为什么需要差分**：
说话人的**发音习惯**（语速、过渡音、连读）在频谱的**动态变化**里体现得更明显。
只用静态特征，两个人说同一个字可能很像；加上差分就能区分"**怎么说**"。

### ⑩ ★ 均值 + 标准差（84 维超矢量）★

**这一步是整个算法最关键的决策。**

```c
for (int d = 0; d < 42; d++) {
    // 沿时间轴求统计量
    feat[d]        = mean(frame_feat[t][d] for t in frames);
    feat[42 + d]   = std (frame_feat[t][d] for t in frames);
}
```

**产出**：42 个均值 + 42 个标准差 = **84 维**

**为什么不用"帧平均"（只取均值）**：
- 只取均值 → 丢失了"**这个人的特征有多稳定**"这一信息
- 标准差本身也是说话人特征：有人发音很稳（std 小），有人忽高忽低（std 大）

**为什么不用 CMN（倒谱均值归一化）**：
CMN 的做法是"对每一维减去自己这段音频的均值" —— 这会**把说话人的个性信息一起减掉**。
然后是帧平均 → 均值恒为 0 → **整个特征向量全是 0**（这就是 v4 版本"特征全为 -0.00"的原因）。

> **核心结论**：
> **归一化必须基于"所有注册样本的全局统计量"，不能每段自己算。**
> 因为"每段自己减均值"会同时抹掉说话人**之间**的差异和说话人**内部**的差异 ——
> 而前者恰恰构成了声纹。

### ⑪ 比对：全局 z-score + 加权欧氏 + 高斯核

```c
// ① 全局 z-score（s_st.mean/std 是**所有注册样本汇总**的统计量）
float va = (a[d] - s_st.mean[d]) / s_st.std[d];
float vb = (b[d] - s_st.mean[d]) / s_st.std[d];

// ② 加权平方欧氏距离
float diff = (va - vb) * s_dimWeight[d];
d2 += diff * diff;

// ③ 高斯核映射到 0~1
similarity = exp(-d2 / (2 * σ²));
```

**为什么用"全局 z-score"**：
84 维里，**c0 相关的维度数值在 100~200 量级，高阶系数和标准差在 1 以下** ——
直接算欧氏距离，**c0 一个维度就能主导整个距离**（v1 版本的失败原因）。

用**全局**均值/标准差把每维压到同一量级，就消除了量纲差异。

**为什么用高斯核而不是简单的 `1/(1+d)`**：
- 高斯核有明确的统计解释（假设特征服从高斯分布时的似然比）
- 输出天然在 `(0, 1]` 区间，**相似度 = 1 当且仅当完全一致**
- 参数只有 σ 一个，**便于自动标定**

### ⑫ ★★ σ 自动标定（本项目的关键创新）★★

**问题**：`σ²` 硬编码成 84（等于特征维数）时，实测 `d² ≈ 350`，
`exp(-350 / 168) = 0.12` —— **所有人的相似度都被压到 0.1 左右**，完全不可用。

**解法**：让"**本人的正常波动**"对应一个固定的目标相似度（0.85），反解 σ²：

```
目标：exp(-d_median² / (2σ²)) = 0.85

两边取对数：-d_median² / (2σ²) = ln(0.85) ≈ -0.1625

解得：σ² = d_median² / (2 × 0.1625) = d_median² / 0.325
```

其中 `d_median²` = **所有注册模板两两之间距离的中位数**。

```c
static void calibrateSigma(void) {
    // ① 收集所有两两距离（5 个模板 ⇒ 10 对）
    for (i...) for (j = i+1...) dists[n++] = normDist2(feats[i], feats[j]);

    // ② 取中位数
    sort(dists); median = dists[n/2];

    // ③ 反解
    sigma2 = median / (2.0 * -log(0.85));

    // ④ 限幅（防极端情况）
    clamp(sigma2, SIGMA2_MIN=15, SIGMA2_MAX=2000);
}
```

**好处**：
- **全自动，不需要人工调参** —— 每个人录完 5 段就自动标定好
- **对不同说话人自适应** —— 有人特征聚得紧（d 小 → σ² 小），有人分散（d 大 → σ² 大）
- **可解释** —— σ² 有明确含义："本人的正常波动尺度"

**实测**：`median d² = 149.8 → σ² = 460.9`（和硬编码的 84 差了 5.5 倍）

## 三、算法迭代 5 版的血泪史

> **这一段是本项目最有价值的部分。**
> 面试官问"你遇到过什么困难"时，讲这个比讲"我做了一个声纹识别系统"强 10 倍。

### v1：原始 MFCC 余弦相似度

**做法**：把 84 维特征当向量，算余弦相似度。

**结果**：不同内容的信号也有 **0.73** 相似度。

**失败原因**：
- 84 维里 **c0（能量）相关的维度数值在 100~200**，而高阶系数和标准差在 1 以下
- 余弦相似度 = `a·b / (|a||b|)` —— **被数值大的维度完全主导**
- 所以"两个人都大声说话"就会被判为相似，哪怕音色完全不同

**教训**：**不做归一化就直接算距离，等于只看能量**。

### v2：逐样本 z-score

**做法**：对每一段音频，**各自**求 84 维的均值和标准差，做标准化后再比。

**结果**：**同一个人变成 −0.76**（负相似度！）

**失败原因**：
- `(x - mean_self) / std_self` 这一步，把"**这个人的特征值有多大**"这个信息**减掉了**
- 举例：本人 c1 一直是 +150，另一个人是 −150。
  各自减去自己的均值后，**两人都变成 0 附近** —— 差异被抹平了
- 剩下的是"**这段音频内部的波动模式**"，而波动模式受说话内容影响远大于受说话人影响

**教训**：**归一化用的统计量，必须是"跨样本共享的"，不能每段自己算**。
否则你减掉的不只是量纲，还包括**你要找的那个信号**。

### v3：加权 + L2 归一化

**做法**：给每维加权重（抑制 c0），然后整体 L2 归一化。

**结果**：本人 **0.99**（很好），但**多人说话视频也是 0.994** —— **区分度消失**。

**失败原因**：
- L2 归一化把向量长度归一了，**只剩方向**
- 而方向主要由"能量在 26 个 Mel 频段的相对分布"决定，这个分布**对所有人都差不多**（都符合语音的普遍频谱特性）
- 结果所有人都"很像"

**教训**：**区分"人"的信息不在"频谱的平均形状"，而在"偏离平均的程度"**。

### v4：CMN + 帧平均

**做法**：先做倒谱均值归一化（CMN，每帧减去整段的平均倒谱），再对帧求平均。

**结果**：特征**全部是 −0.00**，交叉验证矩阵**全是负数**。

**失败原因**（这是最典型的一个逻辑矛盾）：
1. CMN 让**每一维在时间轴上的均值 = 0**
2. 然后再**沿时间轴求平均** → **均值必然是 0**
3. 所以 42 个均值维度**全变成 0**，只剩 42 个标准差维度
4. 而标准差维度又被 z-score 除了一个接近 0 的数 → 数值爆炸/变成噪声

**教训**：**CMN 和"帧平均"这两个操作在数学上互斥** ——
前者把均值清零，后者靠均值携带信息。**不能同时用。**

### v5（最终版）：均值 + 标准差 + 全局 z-score

**做法**：
1. 42 维动态特征（14 静态 + 14 Δ + 14 ΔΔ）
2. 对每一维取**均值 + 标准差**（沿时间轴），得 84 维
3. **全局** z-score（统计量来自所有注册样本）
4. 加权欧氏距离
5. 高斯核 + **σ 自动标定**

**结果**：

| 指标 | 值 |
|---|---|
| 同一人 3~5 段的一致性 | **0.830 ~ 0.879** |
| 本人验证 | **0.59 ~ 0.73** |
| 他人验证 | **0.49 ~ 0.52** |
| **区分度** | **约 0.2** ✅ |

**为什么这次对了**：
- **保留了个性信息**：均值维度没有被自己减掉
- **保留了稳定性信息**：标准差维度也参与
- **量纲统一**：全局 z-score 消除了 c0 的主导
- **尺度自适应**：σ 自动标定让"本人正常波动 = 0.85"

## 四、模板管理

### 注册（Enrollment）

```c
// 最多 5 个模板，至少 2 个才能启用验证
#define SPK_MAX_TEMPLATES   5
#define SPK_MIN_TEMPLATES   2

bool spkEnroll(const float *feat) {
    memcpy(s_st.feats[s_st.count], feat, sizeof(float) * MFCC_FEAT_DIM);
    s_st.count++;
    s_st.enrolled = (s_st.count >= SPK_MIN_TEMPLATES);
    recomputeStats();      // 重算全局 mean/std
    calibrateSigma();      // 重标定 σ²
}
```

**为什么需要多段**：
- 1 段无法计算"两两距离"，σ 无从标定
- 3~5 段能覆盖"**本人正常波动**"的范围，验证时更鲁棒

### 验证（Verification）

```c
float spkVerify(const float *feat, bool *pass) {
    float best = 0;
    for (int i = 0; i < s_st.count; i++) {
        float s = normCosine(feat, s_st.feats[i]);
        if (s > best) best = s;          // 取与**最像的那一段**的相似度
    }
    *pass = (best >= s_st.threshold);
    return best;
}
```

**为什么取 max 而不是 mean**：
- 用户这次说话的**语速/音量/内容**可能和某一段模板特别接近
- **用最大值**相当于"只要有任何一个模板能匹配上就通过" —— 更宽容、更符合实际
- 用平均值会让"这次和某个模板差异大"拉低总分，导致**本人被误拒**

### 持久化（NVS）

```c
#define SPK_STATE_MAGIC   0x564C4B05UL   // "VLK" + 版本号 5
```

**为什么要 magic**：
- 特征维度经历过 **14 → 42 → 84** 三次变化
- NVS 里的旧数据**布局完全不同**，不校验就会读到错位的值
- 表现是"**相似度乱跳，时好时坏**" —— 极难排查

**现在**：magic 不匹配 → 自动丢弃 + 提示重新注册。

## 五、阈值怎么定

### 实测数据

| 说话人 | 相似度范围 |
|---|---|
| **本人** | 0.591 ~ 0.732 |
| **他人**（多人说话视频）| 0.486 ~ 0.524 |

### 推荐阈值：**0.52**

| 阈值 | 本人余量 | 他人余量 | 评价 |
|---|---|---|---|
| 0.62（默认）| ⚠️ 0.591 会被误拒 | 0.06 | 太严 |
| **0.52** | ✅ 0.07 | 0.00~0.03 | **平衡** |
| 0.45 | 0.14 | ⚠️ 0.524 的他人会通过 | 太松 |

### ⚠️ 一个诚实说明

**0.52 这个阈值，他人样本中的 0.524 恰好会通过** —— 这是本方案的**局限**。

**根因**：
- 8 kHz 采样只覆盖 0~4 kHz，**丢掉了 4~8 kHz 的高频共振峰**（那部分对个体区分很关键）
- 只有 84 维、**没有做信道补偿**（麦克风频响 + 房间混响都会引入共性偏差）
- 训练样本只有 3~5 段，**模板覆盖不足**

**如果要提升，方向是**（也是面试时可以讲的"下一步"）：
1. **采样率提到 16 kHz**（需要改 F103 的 TIM2 分频 + 上传带宽翻倍 → 需换 460800 波特率）
2. **加 GMM-UBM 或 i-vector**（业界标准的小样本声纹方案）
3. **做时长规整**（把不同长度的语音规整到统一时长再取统计量）

> **但当前的目标是"能完整跑通、能演示、能讲清楚原理"** ——
> 84 维 MFCC + 高斯核的区分度 0.2，已经足够支撑一个可信的门禁演示。

## 六、性能数据

| 项目 | 值 | 说明 |
|---|---|---|
| **MFCC 耗时** | **56 ms** | 98 帧 × (256 点 FFT + 26 滤波器 + DCT) |
| 单帧耗时 | ~0.57 ms | 56 / 98 |
| FFT 耗时 | ~0.1 ms/帧 | 256 点基 2 = 8 级 × 128 蝶形 |
| 内存占用 | 特征 84 × 4 B = 336 B | 单个模板 |
| 5 个模板 | ~1.7 KB | 加上 mean/std |
| NVS 存储 | 2368 B | 整个 SpkState 结构 |

**为什么 56 ms 是可接受的**：
- 端到端 1.3 秒里，采集占 1000 ms、上传占 723 ms，**推理只占 4%**
- 也就是说，**优化 FFT 对总延迟几乎没有帮助** —— 瓶颈在采集和传输
- 这就是为什么没有上 ESP32 的 SIMD/DSP 指令优化（收益 < 5 ms）

## 七、可复用的算法知识

| 知识点 | 在这里怎么用的 | 为什么重要 |
|---|---|---|
| **短时傅里叶分析** | 25 ms 分帧 + 加窗 + FFT | 语音是非平稳信号，只能"短时"当平稳处理 |
| **Mel 刻度** | 26 个三角滤波器 | 人耳非线性感知，线性频段不匹配 |
| **倒谱分析** | log + DCT | 把"激励 × 声道"变成加法，分离声源和声道 |
| **动态特征（Δ/ΔΔ）** | 一阶/二阶差分 | 捕捉发音习惯，区分"怎么说" |
| **归一化陷阱** | 全局 vs 逐样本 z-score | **归一化统计量的选择决定了信息是否被抹掉** |
| **核方法** | 高斯核 `exp(-d²/2σ²)` | 把距离变成 0~1 的相似度，且可解释 |
| **参数自动标定** | σ² 由模板距离反解 | 避免"魔法数字"，让系统自适应 |
| **模板匹配 vs 训练** | 5 段模板取 max | 小样本场景下比训练模型更实际 |
